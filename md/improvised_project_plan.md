# 🚧 The Improvised Project Plan (Current State)

This document details exactly what the project **has become** due to the improvisations and pivots made during development. This is the detailed architecture of the current running system (Next.js + Tailwind + FastAPI Simulators).

---

## 1. The Core Pivot: From "Live Telemetry" to "Heuristic Simulation"

The original master plan called for integrating live APIs (AISstream, OpenSky, OSRM) via a corporate proxy, governed by Operations Research (OR) and Six Sigma frameworks. 

**The Improvisation:** 
Because setting up and authenticating real-world live APIs can be fragile and requires paid keys, we pivoted to a **Simulation-First Architecture**. Instead of tracking real ships and planes, the backend generates highly realistic synthetic telemetry based on the historical DataCo dataset (172k records).

## 2. Frontend: The Google Stitch / Next.js Pivot

The original plan called for a `React + Material UI (Vision UI Pro)` dashboard.

**The Improvisation:**
You provided a series of massive, highly stylized HTML prototypes generated by **Google Stitch**. To utilize these premium designs without rewriting them from scratch:
1. **Extraction Script:** I wrote Python scripts (`convert_html_to_jsx.py`) to crawl the Stitch HTML, extract the DOM, and convert it into React JSX.
2. **Framework Shift:** Because the Stitch designs relied heavily on modern CSS and SVG layouts, we scaffolded a **Next.js 16 (App Router)** environment with **Tailwind CSS v4** instead of Material UI.
3. **Component Assembly:** We broke the HTML into 5 major React components:
   - `NexafreightPremiumDashboard` (Overview & Map)
   - `NexafreightPredictiveAnalyticsDashboard` (KPIs & XGBoost metrics)
   - `NexafreightLiveShipmentsTable` (Paginated Cargo Data)
   - `DemurrageFinancialTracking` (Financials & Risk)
   - `SmarttrackAiChat` (AI Copilot Interface)

## 3. Backend: The FastAPI Simulation Engine

To feed the new Next.js UI, the backend (`backend/app.py`) was rewritten to serve synthetic, dynamic data streams.

### Endpoints Improvised:
1. **`GET /api/shipments` (The Core Data Engine)**
   - Reads the raw DataCo PostgreSQL database.
   - **Improvisation:** Injects a mocked `late_risk_probability` (0.0 to 1.0) and calculates a fake `$300/day` demurrage penalty on the fly, rather than relying on the actual XGBoost model predictions.
2. **`GET /api/congestion` (The Map Telemetry)**
   - **Improvisation:** Instead of hitting Open-Meteo or AISstream for real port weather/traffic, this endpoint mathematically simulates wait times (0–12 days) for global ports and assigns severity flags (Critical/Moderate/Normal).
3. **`GET /api/market-simulator` (Spot Rates)**
   - **Improvisation:** Generates randomized, fluctuating spot rates (e.g., $1500 - $3500) for major trade lanes (Shanghai -> LA).
4. **`GET /api/emissions` (Scope 3 Tracker)**
   - **Improvisation:** Simulates carbon output (e.g., 420.5 Tons CO2) to populate the Regulatory UI panels.

## 4. The Interactive Map (`GlobalFreightMap.tsx`)

The Google Stitch prototypes had a static placeholder image for the map. 

**The Improvisation:**
We installed `react-simple-maps` and `d3-geo` to build a live WebGL/SVG map. 
- It plots curved oceanic flight/freight paths between major hubs.
- It displays pulsating markers at ports.
- It fetches data from the `/api/congestion` simulator to show dynamic wait times in hover tooltips.
